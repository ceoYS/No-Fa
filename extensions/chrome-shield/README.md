# NoF 실드 — Chrome 차단 프로토타입 (chrome-shield)

> Status: **P1.0 PoC, 로컬 전용**. Manifest V3 · `declarativeNetRequest`.
> 이 프로토타입은 Chrome 데스크톱 전용이며, iOS·Android·SNS·이미지 모자이크 차단이 아니다.

NoF 실드의 "실제로 동작하는 첫 차단"을 가장 낮은 리스크로 보여 주는 Chrome 확장
프로토타입이다. **해롭지 않은 테스트 신호 하나(`nof-test-risk-signal`)** 만 막아,
"막힘 → 잠깐 멈춤" 흐름이 진짜 브라우저 탐색에서도 도는지 검증한다. 실제 성인 사이트
목록이나 검색어는 담지 않는다.

---

## 무엇을 하나

- 최상위 내비게이션(주소창 이동·검색)의 URL/검색어에 `nof-test-risk-signal` 이 들어가면,
  그 페이지를 열지 않고 **앱 내 멈춤 페이지(`blocked.html`)로 redirect** 한다.
- 멈춤 페이지는 **어디로 가려 했는지 보여주지 않고**, 그 자리에서 5분 멈춤 타이머를 돌린다
  ("잠깐 멈춤으로 가기").
- 그 외 주소는 **그대로 통과**한다(아무것도 막지 않는다).

## 무엇을 하지 않나

- 실제 성인 사이트/검색어를 막지 않는다 — 막는 건 무해한 테스트 토큰 한 개뿐이다.
- 모바일(iOS·Android), 타사 SNS 앱, 이미지 모자이크는 **하지 않는다**(P2/P3 영역).
- 네트워크 요청, 원격 코드(CDN), 외부 API가 **없다**. 방문 기록을 어디로도 보내지 않는다.
- 사용자에게 위험한 주소를 직접 찾거나 붙여넣게 하지 않는다.

---

## 설치 (개발자 모드)

1. Chrome에서 `chrome://extensions` 를 연다.
2. 우측 상단 **개발자 모드**를 켠다.
3. **압축해제된 확장 프로그램을 로드** → 이 폴더(`extensions/chrome-shield`)를 고른다.

> **회사·조직 관리 브라우저 주의:** 로드할 때 `Extension installation is blocked by policy`
> 가 뜨면, 회사/조직의 브라우저 정책이 *압축해제된 확장 로드*를 막은 것이다 — NoF 코드
> 결함이 아니다. 정책을 우회하지 말고, 허용된 개인 PC 또는 비관리 브라우저에서만 테스트한다.
> 그런 환경이 없으면 이 PC에서는 실제 차단 테스트를 완료할 수 없다(앱·확장 코드와는 무관).

## 빠른 설정 (앱과 같은 순서)

NoF 앱 `실제 차단 테스트` 화면의 `Chrome 확장 준비` 카드와 같은 순서다. **압축해제 설치**이며,
**Chrome 웹 스토어 설치는 아직 아니다.**

1. `chrome://extensions` 를 연다.
2. **개발자 모드**를 켠다.
3. **압축해제된 확장 프로그램을 로드** → `extensions/chrome-shield` 폴더를 선택한다.
4. 확장 카드의 **확장 ID**를 복사한다.
5. NoF 앱 `Chrome 확장 연결` 칸에 확장 ID를 **붙여넣고 연결 확인**을 누른다.
6. `차단 테스트용 값`을 적고 **이 브라우저 차단 규칙에 반영**을 누른다.
7. 그 값이 든 주소를 열어 NoF **잠깐 멈춤**으로 가면 차단 테스트 성공이다.

> **한계(정직):** 압축해제 확장은 ID가 고정되지 않는다(경로 기반·무작위). 다시 로드하면 바뀔 수
> 있어, 그때는 앱에 다시 붙여넣는다. Chrome 웹 스토어 패키지·고정 프로덕션 ID 는 아직 없다.
> Chrome 데스크톱 한정이며, 모바일·기기 전역·타 앱 차단은 하지 않는다.

## Web Store 준비 상태 (RC-14)

RC-14 는 **Chrome 웹 스토어 등록 자체가 아니라 등록 준비(readiness)** 단계다. 정직하게:

- **Chrome 웹 스토어에는 아직 올라가지 않았어요.** 자동 설치되지 않는다.
- 지금은 위 절차대로 **압축해제(언팩)로 직접 로드**하는 로컬 개발 빌드다.
- 연결은 수동이다 — **확장 ID 를 직접 복사해서 앱에 붙여넣어요.** 압축해제 ID 는
  고정되지 않아(경로 기반·무작위) 다시 로드하면 바뀔 수 있고, **고정 프로덕션 ID 는 아직 없다.**
- **이 Chrome 브라우저에서만** 작동한다. **기기 전체·다른 앱·모바일은 막지 않아요.**
- **AI 자동 감지는 하지 않아요.** 위험한 주소를 자동으로 분류하거나 큐레이션하지 않는다.
- **사용자가 직접 확인한 구체 값만** NoF 웹앱이 `SET_BLOCK_RULES` 로 보낸다. 앱의
  **상황 메모는 브라우저 규칙으로 보내지 않아요** — 그 자체로는 차단 토큰이 되지 못한다.

스토어 제출 전 준비 항목(아이콘·매니페스트 카피·권한 정당화·프라이버시·스크린샷·남은 차단 요소)은
[`../../docs/NOF_RC14_WEB_STORE_READINESS.md`](../../docs/NOF_RC14_WEB_STORE_READINESS.md) 에 정리했다.

## 테스트

**막히는 경우 (테스트 신호 닿음)**
- 주소창에 `example.com/?q=nof-test-risk-signal` 처럼 테스트 토큰이 든 주소를 입력하거나,
  검색창에 `nof-test-risk-signal` 을 검색한다.
- → 대상이 열리지 않고 NoF "잠깐 멈춤" 페이지로 이어진다. "잠깐 멈춤으로 가기"로 5분
  타이머가 시작된다.

**통과하는 경우 (안 닿음)**
- `example.com` 같은 평범한 주소로 이동한다.
- → 차단 없이 그대로 열린다.

> 대소문자는 무시한다(`NOF-TEST-RISK-SIGNAL` 도 막힌다). main_frame(탭 이동)만 대상이며,
> 페이지 안의 하위 리소스는 건드리지 않는다.

## 파일 구성

| 파일 | 역할 |
|------|------|
| `manifest.json` | MV3 매니페스트. `declarativeNetRequest` 권한 + 정적 룰셋 등록, 모듈 서비스 워커. |
| `rules.json` | 정적 룰: 테스트 토큰 → `blocked.html` 로 redirect (main_frame, 대소문자 무시). |
| `signals.js` | 로컬 위험 신호 모델 + `buildDynamicRules()`(신호 → 동적 룰). 무해한 테스트 토큰만. |
| `service_worker.js` | 동적 룰 동기화(`updateDynamicRules`) + 같은-확장 `onMessage` + RC-7 앱 브리지(`onMessageExternal`). |
| `blocked.html` / `blocked.js` | NoF 멈춤 페이지. 대상 비표시, 로컬 5분 타이머. |
| `popup.html` / `popup.js` | 상태·테스트 신호 표시, 설정 열기. |
| `options.html` / `options.js` | 신호 목록 보기 + 앱 동기화 설계 설명. |

## 앱 ↔ 확장 연결 (RC-7)

지금은 정적 룰(`rules.json`, id 1)이 테스트 토큰 하나를 막는 **항상 켜진 데모**다. 동적 룰은
비어 있다(id ≥ 1000 예약). RC-7에서 NoF 앱과 확장을 **실제로** 잇는 첫 슬라이스를 추가했다.

**매니페스트 `externally_connectable`** — 일반 웹 페이지는 아래 출처에서만 확장에 말을 걸 수 있다:

```
"externally_connectable": { "matches": [
  "https://nof-mauve.vercel.app/*",
  "http://localhost/*",
  "http://127.0.0.1/*"
] }
```

> Chrome 매치 패턴은 **포트를 지원하지 않는다.** `http://localhost:4173/*` 처럼 포트를 넣은
> 패턴은 무효라 매니페스트 로드가 통째로 거부된다. 포트 없는 `http://localhost/*` 가 모든 개발
> 포트(4173·5173 등)를 포함한다.

**메시지 규약** — 외부 페이지는 `onMessageExternal` 로 닿는다(같은-확장 전용 `onMessage` 와 별개).
모든 응답은 `{ ok, ... }` 구조다:

| 타입 | 동작 | 응답 |
|------|------|------|
| `PING` | 살아있는지 확인 | `{ ok, name, version }` |
| `GET_STATUS` | 현재 동적 룰 수 | `{ ok, dynamicRuleCount, testSignal, name, version }` |
| `SET_TEST_SIGNAL` | 무해한 테스트 토큰 동적 룰 설치 | `{ ok, count, testSignal }` |
| `SET_BLOCK_RULES` | 정규화한 신호 배열 → 동적 룰 | `{ ok, count }` |
| `CLEAR_RULES` | 동적 룰 제거 | `{ ok, removed }` |

신호 매핑 원칙은 그대로다: 앱이 **추상 위험 신호**를 **앱이 관리하는 큐레이션 토큰**으로 바꿔
보낸다. 사용자가 위험한 주소를 직접 찾지 않는다(그 검색 자체가 재발 트리거다). 실제 사용자
도메인 → 동적 룰 → 리다이렉트 증명은 **RC-8** 영역이다.

**확장 ID** — 압축해제(언팩) 확장은 ID가 무작위라 페이지가 자동으로 알 수 없다. 그래서 앱
화면(`실제 차단 테스트`)에서 사용자가 ID를 **붙여넣어** 로컬에 저장하고 `연결 확인`(PING)을
누른다. PING 이 실제로 응답할 때만 `연결됨` 으로 표시한다 — 응답이 없으면 절대 연결됐다고
표시하지 않는다.

> **검증됨 (WSL 헤드리스 Chromium, 2026-06-16):** 이 매니페스트·워커 변경은 코드
> 게이트(`check:nof`) 통과에 더해, 압축해제 확장을 실제 Chromium(헤드리스, CDP)에 로드해
> 앱↔확장 왕복을 자동 검증했다. 증명된 것:
> - 확장 로드됨 · 확장 ID 사용(압축해제라 ID 무작위 — 해당 폴더 경로 고정 ID)
> - 앱 `PING` 에 확장이 실제 응답(`onMessageExternal` 왕복)
> - `SET_TEST_SIGNAL` 전송 → 동적 룰 수 0 → 1
> - 테스트 토큰 URL → `blocked.html` 로 redirect
> - 평범한 URL 은 redirect 되지 않음(오탐 없음)
> - 앱은 실제 응답 전에는 `연결됨` 을 표시하지 않음
>
> **아직 아닌 것(정직):** 회사·조직 관리 Windows Chrome GUI 에서의 검증은 아직 안 했다(아래
> 수동 절차로 확인). Chrome 웹스토어 패키지·고정 프로덕션 확장 ID 는 없다. 사용자가 저장한
> 실제 도메인 → 동적 룰 설치·리다이렉트 증명은 **RC-8** 영역이다. 모바일·기기 전역·타 앱
> 차단은 구현하지 않았다.

### 수동 연결 스모크 (Chrome 데스크톱)

1. 위 **설치** 절차로 이 폴더를 압축해제 로드한다.
2. `chrome://extensions` 에서 이 확장의 **ID**(32자)를 복사한다.
3. NoF 앱 → `보호 설정` → `차단 테스트하기` 화면(실드 → Chrome 확장 테스트로도 도달)을 연다.
4. **확장 ID** 칸에 붙여넣고 **연결 확인** 을 누른다 → 응답하면 `연결됨` 이 뜬다.
5. **테스트 신호 보내기** 를 누른 뒤, 주소창에 `example.com/?q=nof-test-risk-signal` 을 연다
   → 페이지 대신 NoF **잠깐 멈춤**(`blocked.html`)으로 이어지면 성공이다.
6. 평범한 주소(`example.com`)는 차단 없이 그대로 열린다.

## 저장 신호 → 동적 차단 규칙 (RC-8)

RC-7은 앱↔확장 연결과 **정적** 테스트 토큰까지 증명했다. RC-8은 그 다음 칸을 채운다:
**사용자가 적은 구체적 신호** 하나를 `SET_BLOCK_RULES` 로 보내 이 브라우저의 **동적**
declarativeNetRequest 룰로 설치하고, 그 값이 든 주소가 실제로 `blocked.html` 로 redirect
되는지까지 증명한다.

**흐름** — 앱 `실제 차단 테스트` 화면 → `브라우저 차단 규칙 반영` 카드:

1. `연결 확인`(PING)으로 확장이 응답하는지 먼저 확인한다.
2. `차단 테스트용 값`(기본값: 무해한 예약 도메인 `example.com`)을 적는다.
3. `이 브라우저 차단 규칙에 반영` → 앱이 `sendBlockRules()` 로 `SET_BLOCK_RULES` 를 보낸다.
4. 확장이 `ok:true` 로 응답할 때만 "차단 규칙 N개를 반영했어요" 를 표시한다. 응답이 없으면
   "아직 연결되지 않았어요" 로 정직하게 멈춘다 — 절대 반영했다고 거짓 표시하지 않는다.

**정직 — 저장한 위험 신호는 그대로 보내지 않는다.** 앱의 위험 신호 목록은 카테고리·상황 같은
**추상 라벨**이라 그 자체로는 브라우저 매칭 토큰이 되지 못한다. 추상 라벨을 룰처럼 설치하면
"막히는 척"이 되므로, RC-8은 저장 신호를 **개수만** 보여 주고, 실제 룰은 사용자가 적는 구체적
테스트 값으로 만든다. 큐레이션된 성인 사이트 목록이 아니다.

**정규화(서비스 워커, 보수적):** `normalizeSignals()` 가 들어온 값을 trim·소문자화하고, 빈 값과
위험 스킴(`javascript:`/`data:`/`chrome-extension:` 등)을 버리고, `http(s)://` 스킴은 벗겨 호스트만
남기고, 중복을 없애고, 개수를 `MAX_BLOCK_RULES`(20) 로 제한한다. 그 뒤 기존 `buildDynamicRules()`
로 동적 룰을 만든다 — 새 엔진이 아니라 RC-7과 같은 로컬 경로를 재사용한다. 매칭은 **부분 문자열**,
**대소문자 무시**, **main_frame(탭 이동)만** 이다. 예: `example.com` 은 `https://example.com/` 과
`https://example.com/길` 을 모두 잡는다(부분 문자열이라 폭이 넓다는 점은 정직하게 고지한다).

**자동 스모크:** [`scripts/nof-extension-smoke.mjs`](../../scripts/nof-extension-smoke.mjs)
(`npm run qa:ext`). 이미 확장을 로드해 둔 Chrome/Chromium 의 CDP 엔드포인트(`NOF_CDP_URL`)에
붙어, 확장 ID 자동 탐색 → 앱에 ID 저장 → PING → **새** 테스트 토큰을 `SET_BLOCK_RULES` 로 전송 →
동적 룰 수 증가 확인 → 그 토큰이 든 로컬 주소가 `blocked.html` 로 redirect 되는지 확인 → 토큰 없는
주소는 통과하는지 확인까지 자동으로 돈다. 확장이 안 보이거나 CDP 가 없으면 **정직하게 실패**하고
실행 방법을 출력한다(없는 통과를 만들지 않는다). 정적 토큰(`nof-test-risk-signal`)이 아닌 **새**
토큰으로 막으므로, 막힘이 정적 룰이 아니라 **동적 룰**에서 왔음을 증명한다.

**아직 아닌 것(정직):** Chrome 웹스토어 패키지·고정 프로덕션 확장 ID 는 없다(압축해제 ID 는
무작위/경로 고정). 큐레이션된 성인 카테고리 목록은 없다. redirect 도착지는 확장 안
`blocked.html`(로컬 5분 타이머)다. 웹앱으로 돌아가는 딥링크는 **RC-10**에서 더했다(아래). 모바일·기기 전역·타 앱·
다른 브라우저 차단은 하지 않는다 — 이 Chrome 데스크톱 한정이다.

## 멈춤 페이지 → 앱 이어가기 (RC-10)

RC-8/RC-9 는 신호 → 동적 룰 → `blocked.html` redirect 까지 증명했다. 그동안 `blocked.html`
은 확장 안 로컬 5분 타이머라 앱으로 돌아갈 길이 없었다. RC-10 은 그 고리를 닫는다 — 멈춤
페이지에 **앱으로 이어가기** 두 가지를 더한다.

- **오늘 기록으로 남기기** → NoF 앱 `오늘 기록` (`?from=shield&to=record`)
- **잠깐 멈춤 계속하기** → NoF 앱 `잠깐 멈춤` (`?from=shield&to=urge`)

**정직 — 대상 주소는 넘기지 않는다.** 딥링크는 `from=shield` 와 거친 목적지(`to=urge|record`)
만 담는다. 어디로 가려 했는지(주소·검색어)는 읽지도, 저장하지도, 보내지도 않는다. 앱은
잘못된/없는 목적지를 홈으로 안전하게 떨군다. 앱이 "무엇을 막았는지" 안다고 주장하지 않는다.

기본 도착지는 프로덕션 앱(`https://nof-mauve.vercel.app`)이다. 로컬 프리뷰로 끝까지 검증할
때만 `localStorage['nof.shieldAppBase']` 로 베이스를 덮어쓴다(확장 스모크 전용 훅 — 프로덕션
사용자 흐름은 이 값을 설정하지 않는다). 네트워크 호출이 아니라 사용자가 누르는 이동이다.

자동 스모크(`npm run qa:ext`)는 이 흐름까지 검증한다: `blocked.html` 을 열어 두 이어가기
버튼과 그 딥링크(`from=shield&to=record|urge`)를 확인하고, 베이스를 로컬 앱으로 덮어쓴 뒤
각 버튼을 실제로 눌러 `오늘 기록` / `잠깐 멈춤` 화면에 도착하는지까지 클릭한다.

## 프라이버시 · 한계

- **온디바이스 전용**: 방문 내용·신호를 서버로 보내지 않는다.
- **마찰이지 벽이 아니다**: 시크릿 창·다른 브라우저·확장 끄기로 우회할 수 있다. 정직하게
  고지한다.
- **Chrome 데스크톱 한정**: 기기 전역(OS) 차단은 P2, SNS 이미지 모자이크는 P3 연구 영역이다.

자세한 단계 정의는 [`../../docs/NOF_SHIELD_ROADMAP.md`](../../docs/NOF_SHIELD_ROADMAP.md)
의 **P1.0** 절을 본다.
