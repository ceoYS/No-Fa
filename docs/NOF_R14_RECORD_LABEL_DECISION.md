# R-14 기록 점 라벨 결정 패킷 (C2)

작성일: 2026-06-10 · 상태: **제품 오너 결정 필요 — 결정 전 코드 변경 금지**
출처: UI_BENCHMARK_REVIEW R-14 · NOF_PRD_SPEC_ALIGNMENT_AUDIT C2 · COPY_POLICY §10.6 · UI_BENCHMARK "PRD 수정 전 임의 변경 금지"

## 0. 결정해야 하는 것

기록 캘린더 점(dot) 4상태의 사용자 라벨. 현재 구현과 PRD 감수 권고안이 갈라져 있고,
권고안 자체가 COPY_POLICY 내부 모순을 안고 있어 단순 동기화로는 수렴이 안 된다.

점 상태의 실제 파생 로직 (`src/constants/recentDays.js`):

| 내부 상태 | 실제 파생 조건 (소스 기준) |
|---|---|
| `kept` | 그 날 못 지킨 규율 0 + 지킨 규율 ≥1 |
| `recovered` | 못 지킨 규율 ≥1 **+ 복기 완료(`badges.reflected`)** |
| `needs_check` | 못 지킨 규율 ≥1 + 복기 전 · 또는 재발/다시 시작한 날 |
| `untracked` | 기록 없음 (현재 런 이전 등) |

⚠️ 핵심 사실: `recovered`를 켜는 것은 **복기**다. 회복 루틴·회복 행동이 아니다.
라벨 선택은 이 파생 로직과 정직하게 맞아야 한다 (프라임 디렉티브).

## 1. 선택지 비교

### A안 — 현행 구현 유지: `지킨 날 / 복기한 날 / 돌아볼 날 / 기록 전`

- 위치: `recentDays.js:34-39` (CALENDAR_LABEL) + `CalendarScreen.jsx:100` 도움말 한 줄.
- 장점: **파생 로직과 정확히 일치** — 복기로 켜지는 상태를 "복기한 날"로 부른다.
  비난·점검 어휘 0. 코드 변경 0.
- 단점: 잠긴 PRD §0.5.3.2 어휘와 분기 상태 지속. "돌아볼 날"이 미래형으로 읽혀
  모호함(해야 할 일? 지나간 날?) — R-14가 애초에 잡힌 이유의 절반.

### B안 — PRD 감수 권고: `지킨 날 / 회복한 날 / 확인 필요 / 기록 전`

- 출처: COPY_POLICY §10.6 승인 표 · FAILENDAR_TO_NOF_ADAPTATION · SPEC_KIT_INDEX §0.6.5.
- 장점: 잠긴 PRD 문서 계열과 표면상 일치.
- 단점 1 — **정직성 위반 위험**: §10.6 정의상 `회복한 날` = "회복 행동 1개 이상 완료"인데
  구현은 복기만 본다. 라벨만 바꾸면 하지 않은 행동(회복 루틴)을 한 것처럼 읽힌다.
  채택하려면 파생 로직도 회복 루틴 배지(`routineDone`)를 보도록 같이 바꿔야 한다.
- 단점 2 — **COPY_POLICY 내부 모순**: §0.6.2(규율)는 `확인 필요`를 "제거된 어휘"로
  명시했는데 §10.6(캘린더)은 승인 라벨로 둔다. 같은 정책 문서가 같은 단어를
  한 곳에선 금지, 한 곳에선 승인. 채택하면 이 모순을 PRD 차원에서 먼저 해소해야 한다.
- 단점 3: `확인 필요`는 점검·검사 어휘 — 비감시·비처벌 원칙과 톤 충돌(§0.6.2가
  제거한 이유와 동일).

### C안 — 제3안 (권장): `지킨 날 / 복기한 날 / 복기 전 / 기록 전`

- `돌아볼 날` → **`복기 전`** 한 단어만 교체.
- 장점 1 — **대칭으로 모호함 해소**: `복기한 날 ↔ 복기 전`이 같은 축의 두 상태(흔들린 뒤
  돌아봄/아직)임이 라벨만으로 드러나고, `기록 전`과 어미가 정렬된다("~전" = 아직,
  사실 서술, 비난 0).
- 장점 2 — 파생 로직과 정확히 일치(복기 기준), 정직성 문제 없음.
- 장점 3 — `복기`는 이미 제품 확립 어휘(복기하기 버튼·복기 완료 배지·오늘 복기하기).
  새 어휘 도입 없음.
- 장점 4 — §0.6.2의 `확인 필요` 제거 결정과 충돌하지 않음.
- 단점: PRD §0.5.3.2 표는 여전히 개정 필요(어차피 A·C 모두 개정 필요, B만 표면상 무개정
  — 그러나 B는 위 모순 해소 개정이 필요해 실질 무개정 선택지는 없음).
- 유의: 재발/다시 시작한 날도 현재 `needs_check` 톤을 쓰므로 `복기 전`이 그 날에도
  표시됨 — 의미상 자연스러움(재발 복기 플로우 존재). 상세 시트엔 이미
  "다시 시작한 날"이 별도 표기됨.

## 2. 권장안

**C안.** 근거: 파생 로직과 라벨의 정직한 일치(프라임 디렉티브) + §0.6.2 어휘 결정과
무충돌 + 모호함 해소를 한 단어 교체로 달성. B안은 라벨-로직 불일치와 정책 내부 모순
두 개를 먼저 풀어야 해서 실비용이 가장 크다.

> **제품 오너 결정 필요.** 이 문서는 권고일 뿐이며, C2는 잠긴 PRD 어휘에 닿으므로
> 오너 결정 → PRD §0.5.3.2·COPY_POLICY §10.6 개정 → 구현 동기화 순서를 지킨다.
> 결정 전까지 제품 코드는 현행(A) 유지.
