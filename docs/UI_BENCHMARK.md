## 사용 규칙

- **레퍼런스에서 가져오는 것은 "원리"뿐이다.** 보호된 UI·로고·에셋·고유 레이아웃·브랜드 디테일은 복제하지 않는다.
- 분류 어휘:
  - **USE** — 우리가 채택해야 할 재사용 가능한 원리
  - **CAUTION** — 유용하지만 그대로 베끼면 위험한 패턴 (조건 명시)
  - **AVOID** — NoF의 신뢰·따뜻함·성숙함·안전을 해치는 패턴
- 모든 항목은 정직성 원칙(가짜 기능 금지)과 `COPY_POLICY.md` 금지 어휘를 전제로 한다.
- "구현 상태"는 2026-06-10 wip/pet-room-scene-mode 브랜치 브라우저 실측 기준이다.

## 1. 다중 절제 카운터 UX (multi abstinence counter)

참고 원리 출처: Finch·Alan·Withings·KinTimer(타이머 표현), Streaks·Habitify·Productive(다중 습관 관리)

**USE**
- 홈은 "선택된 카운터 1개"를 히어로로, 나머지는 카드 리스트로 — 다중을 보여주되 초점은 하나.
- 일 단위 큰 숫자 + 시:분:초 보조 표기. 숫자는 또렷하되 카운트다운 공포감 없음.
- 카드마다 목표(목표 30일)·최장 기록·연결 규율 수 등 "맥락 메타"를 한 줄로.
- 선택 상태는 테두리·배경·`aria-pressed`로 (텍스트 라벨 "보는 중" 금지 — 가드 #27).
- 카운터 추가/편집은 홈에서 직접 진입 (이름·시작 시점·목표 편집).

**CAUTION**
- "최장 기록" 강조 — 동기 부여로는 좋지만, 재시작 직후엔 현재 0과의 대비가 자책을 부른다. 재시작 직후에는 최장 기록을 작게, "다시 시작점" 메시지를 크게.
- 카운터별 진행 바 — 목표 대비 %가 "성적표"처럼 읽히지 않게 색·두께 절제.
- 카운터 수 무제한 — 4~6개 넘으면 홈이 대시보드화되어 위기 CTA가 밀린다. 접기/우선순위 필요.

**AVOID**
- 전체 카운터 동시 리셋 (보호 규칙 #7 위반 — 한 카운터 재발이 다른 카운터를 건드리면 안 됨).
- 랭킹·점수·등급 어휘, 카운터 간 비교 UI.
- 빨간 경고색 리셋 버튼, "DON'T BREAK" 류 협박 카피 (QUITTR 안티패턴).

구현 상태: **구현됨·양호.** 4개 시드 카운터, 선택 시 히어로 갱신, 규율 연결 수 표기, relapse 단일 스코프(가드 #18) 확인. 시드 이름 "금딸"은 어휘 정책 위반 — `UI_BENCHMARK_REVIEW.md` R-2 참고.

## 2. 규율(자기 규칙) 생성 UX (discipline/rule creation)

참고 원리 출처: Streaks·Done·Habitify(습관 생성), Fabulous(루틴 프레이밍)

**USE**
- 규율 = "내가 지키고 싶은 기준" 프레이밍을 화면 머리에 명시 (현재 구현: "나를 벌주기 위한 약속이 아니라…" — 유지).
- 생성 시트: 짧은 라벨 입력 + 카테고리 칩(밤 시간/충동/검색/SNS·숏폼/수면/외로움/스트레스 + 직접 입력) + 카운터 연결 칩.
- "새 카운터도 함께 만들기" — 규율과 카운터 생성을 한 흐름으로 (현재 구현됨, 유지·보호).
- placeholder에 실제 예시 문장 ("예: 밤 11시 이후 침대에서 휴대폰 보지 않기").
- 연결 안 함 선택지 허용 — 모든 규율이 카운터에 종속될 필요 없음.

**CAUTION**
- 템플릿 제안 — 시작 마찰은 줄이지만, 제안이 너무 구체적이면 사용자가 자기 언어로 쓰지 않는다. 제안은 카테고리 수준까지만.
- 규율 개수 — 3개 이상 권장 시점에 "더 추가하세요" 압박 금지. 1개로도 충분하다는 톤.

**AVOID**
- 삭제 유도 UI (보호 규칙 #8 — 명시 요청 없는 삭제 금지; 현재 삭제 경로 없음 유지).
- 위반/벌점/체벌 어휘. "규율 위반 N회" 카운트 표시.
- 강제 자유 텍스트 (enum-first 원칙 — UX_RULES #8).

구현 상태: **구현됨·양호.** 시트 흐름 실측 확인 (`qa-13-addrule-sheet.png`).

## 3. 체크인 UX (check-in)

참고 원리 출처: Headspace·Calm(무드 기록), Done(상태 입력), Mobbin 체크인 패턴군

**USE**
- "1분 기록" 같은 소요 시간 약속 + 프라이버시 선언("밖으로 공유되지 않아요")을 첫 문장에.
- 입력은 전부 선택형: 기분 4칩 / 트리거 복수 선택(+특별히 없음) / 충동 강도 1–5.
- 선택 즉시 시각 피드백 (앰버 테두리·채움 — 현재 구현 양호).
- 규율 상태 점검을 체크인 마지막 단계로 통합 (PRD D1 권고안 — 현재 구현 일치).
- 다음 단계 버튼은 입력 전 비활성 — 비활성 상태가 시각적으로 구분됨.

**CAUTION**
- 이모지 칩 — 장식으로는 무해하지만 유치해질 수 있는 경계. 현재 수준(4개, 보조) 유지, 늘리지 말 것.
- 단계 분할(1/2) — 두 단계까지는 가볍지만 3단계부터 이탈. 규율 수가 많을 때 step2가 길어지는 문제는 세그먼트형 컨트롤로 압축 검토 (R-7).

**AVOID**
- 무드를 점수화·그래프화해서 "오늘 기분이 나빠졌네요" 식 평가 카피.
- 체크인 미완료에 대한 압박 알림 카피 ("아직 체크인하지 않았어요!" — 부드러운 초대형으로만).
- 강제 일기 입력.

구현 상태: **구현됨·양호.** 2단계 흐름·3상태 통합 실측 확인 (`qa-06`~`qa-08`).

## 4. 회복 캘린더 UX (recovery calendar)

참고 원리 출처: Failendar 구조 차용(`FAILENDAR_TO_NOF_ADAPTATION.md`), LIVESTRONG MyQuit(기록 상세), Mobbin 캘린더 패턴군

**USE**
- 이름은 "최근 기록"/"절제 기록" — 기능명이 곧 화면명 (메타포 단독 라벨 금지).
- 기간 선택 칩(7/14/30/이번 달) + 점(dot) 그리드 + 범례.
- 날짜 탭 → DayRecord 상세 시트: 절제 상태·규율 집계·계기 칩·복기 인용·다음 행동·배지.
- "다시 시작한 날도 빨강 없이 따뜻한 톤으로" — 명문화된 무징벌 색 규칙 (현재 화면 카피에 있음, 유지·보호).
- 복기한 날을 별도 톤으로 — 실패가 아니라 "돌아본 날"이라는 상태.

**CAUTION**
- 월 단위 풀 캘린더 — PRD C3상 P0는 스트립+범위 선택까지. 풀 먼슬리 그리드는 빈 칸이 "구멍"으로 읽혀 자책 유발 가능. 기록 밀도가 쌓인 뒤(P1) 재검토.
- 점 색 의미 — 2~4종 이상 늘리면 범례 의존 심화. 현재 4종(지킨/복기한/돌아볼/기록 전)이 상한.
- 점 라벨 어휘는 PRD C2 미결 — 현재 구현(복기한 날/돌아볼 날)과 감수 권고안(회복한 날/확인 필요)이 다름. **PRD 수정 전 임의 변경 금지.**

**AVOID**
- 빨강/X 표시의 실패일, "실패한 날" 라벨 (Failendar 거부 목록).
- 연속 스트릭 끊김을 시각적 단절(체인 끊김 모티프)로 연출.
- 잔디(히트맵) 식 성과 압박.

구현 상태: **구현됨·양호.** 상세 시트까지 실측 확인 (`qa-04`, `qa-05`).

## 5. 펫 그로스 룸 UX (pet growth room)

참고 원리 출처: Finch(펫 톤 모델), Opal gem(상태 기억), Pokémon Sleep(관찰형 캐릭터) — 구조만, 미감 복제 금지

**USE**
- 고양이가 항상 보이는 완성 합성 이미지 (현재 scene mode — 따뜻함·프리미엄 확보, `qa-14` 실측 양호).
- 방 온기 상태 라벨(약함/잔잔함/안정/따뜻함) — 숫자 게이지가 아닌 상태 언어 (PRD §0.5.10 D).
- 간식 = "곁에 놓아두기" hand-off (실제 모션·먹기 연출이 생기기 전까지; 가드 #13·#25).
- 보상은 절제 행동에서만 발생, 마일스톤 잠금은 정직하게 ("아직 받을 수 없어요. 오늘을 채우면 열려요").
- 면책 카피 유지: "이 보상은 절제를 대신하지 않아요."

**CAUTION**
- 고양이 반응 카피("기분 좋아 보여요", "당신을 바라봐요") — 관찰 화법이라 거짓은 아니나, 정적 이미지에서 반복되면 기대를 만든다. scene mode 동안은 방 상태 화법("방이 조금 더 따뜻해졌어요") 비중을 높일 것 (기존 리뷰 P2 동일).
- 펫 의인화 수위 — Finch 수준의 대화형 펫은 NoF 성숙 톤과 충돌. 펫은 말하지 않는다.
- 아이템 배치 — 투명 스프라이트 준비 전까지 "배치 계획(준비 중)" 고정 (보호 규칙 #1·#2·#6).

**AVOID**
- 펫 처벌 상태: 굶음·병듦·죽음·강등 (UX_RULES #4 — 재발 시 펫은 "쉬는 상태"까지만).
- 펫 능력치·레벨 경쟁, 유료 펫 부활/회복.
- 먹는 애니메이션 없는 "먹었어요" 카피 (프라임 디렉티브).

구현 상태: **구현됨·양호(정직성 1건 제외).** 소리 토글이 dev/SPA-fallback 환경에서 죽은 스위치로 노출 — R-1 (P1).

## 6. 재발/회복 플로우 (relapse/recovery flow)

참고 원리 출처: LIVESTRONG MyQuit(재발 기록 분리), Finch(회복 톤), Failendar 전환 교훈

**USE**
- 재발("무너졌어요")과 규율 슬립("못 지켰어요")의 **이중 스코프** — 재발만 타이머 리셋, 슬립은 리셋 없음 (PRD §0.6.3; 현재 구현 일치).
- 재발 확정 전 확인 단계 (가드 #14 — 즉시 리셋 금지).
- 복기 3문항(왜/계기/다음 행동) + 계기 enum 칩 + "한두 줄이면 충분해요" 저마찰 힌트.
- 재발 복기는 필수, 슬립 복기는 선택 — 무게 차등.
- "위기였지만 버텼어요"를 성취로 표면화 ("그 자체로 오늘의 성취예요" — 현재 구현 카피 유지·보호).
- 탈출구 허용 ("조금 이따 할게요") — 복기 강요 금지.

**CAUTION**
- 재발 직후 화면에 펫·보상 노출 — 위로가 되지만 "재발해도 보상"으로 읽히면 안 됨. 복기 완료 후에만 보상 동선.
- 이전 기록 아카이브 표시 — "지난 여정 12일"을 보여주는 건 좋지만 묘비처럼 박제하지 말 것.

**AVOID**
- 재발 직후 결제 제안 (MONETIZATION_POLICY 절대 금지).
- "또 실패했네요", 실패 횟수 강조, 사유 필수 입력 강제.
- 종교적 죄/타락 프레이밍 (Covenant Eyes 안티패턴).

구현 상태: **구현됨·양호.** 복기 화면·확인 시트 실측 확인 (`qa-09`).

## 7. 상점/가챠 수익화 UX (shop/gacha)

참고 원리 출처: Duolingo·Forest·Finch(행동 보상형 상점), `MONETIZATION_POLICY.md` 하드 제약

**USE**
- 코어 루프(타이머·체크인·규율·잠깐 멈춤·복기)는 영구 무료 — 상점은 장식·소모품만.
- 재화(잔불 조각)는 절제 행동으로만 적립; 적립 경로를 상점 안에서 설명.
- 구매 대상은 비확률·고정가 코스메틱/소모품 (현재: 간식 교환 — 정직).
- 잠긴 항목은 잠금 사유를 정직하게 표기.

**CAUTION**
- 시즌/한정 아이템 — 수집 동기는 좋지만 FOMO 카운트다운은 충동 관리 앱의 자기모순. 한정을 하더라도 타이머 압박 없이.
- 현금 결제 도입(P2) — D30 리텐션 + 미성년 보호 정책 선행 조건 (MONETIZATION_POLICY). UI 차원에서도 가격 표시는 차분하게, "지금 사야" 어휘 금지.

**AVOID**
- 랜덤 가챠/루트박스 (MVP·베타 금지 — 정책 명문).
- 스트릭 복구·실패 삭제·차단 해제 판매 (pay-to-win 금지 목록).
- 재발 직후 상점 배너, "무료로는 부족해요" 페이월 카피.

구현 상태: **부분 구현(의도된 범위).** scene mode에서 상점=간식 1종, 테마 숨김 — 정직. 시트 앵커링 이슈 R-5 (P2).

## 8. 저널/복기 다이어리 UX (journal/reflection)

참고 원리 출처: Stoic·Day One(저널 저마찰 패턴), LIVESTRONG(사유 기록), Mobbin 복기 패턴군

**USE**
- 3문항 고정 구조(왜/계기/다음 행동) — 빈 페이지 공포 제거.
- 계기는 enum 칩 재사용 (체크인과 동일 어휘 — 데이터 일관성 + 학습 비용 0).
- 작성 결과가 DayRecord와 배지(복기 완료 등)로 연결 — 쓴 글이 어디에 남는지 보임.
- 따뜻한 비주얼 앵커(고양이 방 썸네일) — 위기 직후 정서 완충.

**CAUTION**
- 과거 복기 열람 — 패턴 학습에 유용하나, 재발 직후 과거 실패 목록을 들이밀면 역효과. 열람은 기록 탭에서만, 복기 작성 화면에서는 오늘만.
- AI 요약/분석(P2 후보) — "당신의 패턴은…" 단정 화법 금지, 제안 화법만.

**AVOID**
- 필수 장문 입력, 최소 글자 수.
- 복기 미작성 패널티(배지 박탈, 펫 시무룩 등).
- 수치심 어휘 일체 (COPY_POLICY §4.1).

구현 상태: **구현됨·양호.** (`qa-09` 실측; 과거 열람은 기록 탭 상세로 분리되어 있음 — 권장 구조와 일치.)

## 9. 스트릭/보상 피드백 (streak/reward feedback)

참고 원리 출처: Duolingo(보상 루프의 절제판), Finch(무징벌 진행), Mobbin 보상 패턴군

**USE**
- 스트릭은 "현재 N일 + 최장 N일" 중립 표기 — 불꽃 카운트다운·체인 끊김 공포 없음.
- 마일스톤(1/3/7/14/30일) 고정 보상 — 예측 가능, 비확률.
- 보상 수령은 명시적 "받기" 버튼 — 자동 지급 팝업 남발 금지.
- 일일 적립 1회 제한(체크인/위기 버팀/복기 각각) — 가드 #3·#7·#8로 보호됨.
- 보상 면책 카피 상시 노출 ("절제를 대신하지 않아요").

**CAUTION**
- 마일스톤 달성 연출 — 축하는 하되 컨페티 폭발류 과잉 연출은 성숙 톤과 충돌. 잔불·온기 모티프 안에서.
- 다음 목표 표시("14일까지 2일") — 동기 부여지만 임박 압박으로 읽히지 않게 보조 텍스트 수준 유지.

**AVOID**
- 스트릭 손실 경고 알림 ("오늘 놓치면 12일이 사라져요!").
- 리그·리더보드·등수 (§0.5.8.1 금지 어휘).
- 보상으로 절제 성과를 구매·복구하는 동선.

구현 상태: **구현됨·양호.** 마일스톤 잠금/수령 실측 확인 (`qa-15`).

## 10. NoF 실드 / 차단 정직성 UX (blocking honesty)

참고 원리 출처: Opal(정직한 한계 고지 + 마찰 프레이밍), One Sec(지연 개입), ScreenZen — 구조만; QUITTR·Fortress류 "완벽 차단" 클레임은 전면 안티패턴

**USE**
- "준비 중" 상태 pill + 현재 카피 "지금 켜고 끄는 스위치를 두지 않은 건, 동작하지 않는 기능을 켜진 것처럼 보이게 하고 싶지 않아서예요" — **이 문장은 NoF 정직성의 모범. 유지·보호.**
- 신호는 추상 4종(카테고리/검색 신호/앱·SNS/상황)만 — 주소/도메인 어휘 금지 (가드 #30).
- 안전 수칙 상시 노출: "위험한 사이트를 직접 찾아 적지 마세요."
- 차단 = 벽이 아니라 마찰; 차단 순간은 "잠깐 멈춤"으로 연결 (목적지 비노출 — 가드 #32).
- 한계 고지: Chrome 데스크톱 전용·모바일/SNS/모자이크 불가·관리형 PC 정책 제한 (현재 확장 안내 화면에 구현됨 — 유지).

**CAUTION**
- 로드맵 노출(확장→Safe Browser→기기 차단) — 기대 관리에 좋지만 단계마다 "곧"이라는 인상을 주면 약속이 된다. 시점 약속 없는 순서만.
- 경고 배너 3연속 스택 — 정직하지만 시각적 피로. 핵심 1블록 + 인라인 보조로 압축 검토 (R-6).

**AVOID**
- 현재형 차단 클레임("막고 있어요") 일체 (가드 #29).
- "완벽 차단·절대 못 봅니다" (COPY_POLICY 금지).
- 사용자에게 위험 사이트 검색·붙여넣기 요청 (보호 규칙 #6).
- 우회 불가 과장, 감시·모니터링 톤, 차단 대상 URL 노출.

구현 상태: **구현됨·모범적.** 실드/Safe Browser/확장 안내 3화면 실측 확인 (`qa-18`~`qa-20`). 카피 1건("프로토타입") 어휘 위반 — R-3.
