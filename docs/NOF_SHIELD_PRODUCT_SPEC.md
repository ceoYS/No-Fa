# NoF Shield — 제품 스펙 (Product Spec)

> Status: **제품 정의 문서**. 작성 2026-06-01.
> NoF 실드는 "자극으로부터 거리를 두는 보호막"이다. 이 문서는 실드가 **무엇인지 / 무엇이
> 아닌지 / NoF의 다른 기능과 어떻게 이어지는지 / 이번 라운드의 UI 플레이스홀더 스펙**을
> 정의한다.
> 함께 보기: [NOF_SHIELD_FEASIBILITY.md](./NOF_SHIELD_FEASIBILITY.md) ·
> [NOF_SHIELD_ROADMAP.md](./NOF_SHIELD_ROADMAP.md)

---

## 1. 한 줄 정의

> **NoF 실드 = 자극적인 사이트·검색·앱과 나 사이에 "마찰"을 만들어, 충동과 행동 사이의
> 틈을 넓혀 주는 보호막.**

실드는 "완벽한 벽"이 아니라 **"한 번 더 멈추게 하는 문턱"** 이다. 이 프레이밍은 정직성과
직결된다 — 어떤 차단도 우회 가능하므로, 우리는 "막아준다"가 아니라 "멀어지게 돕는다"로
말한다.

---

## 2. 실드가 다루는 것 (What Shield does)

| 코드 | 기능 | 사용자 가치 | 단계 |
|------|------|-------------|:---:|
| B1 | 성인 사이트·도메인 차단 | 알려진 자극 사이트를 열기 어렵게 | P1 |
| B2 | 자극적인 검색어 차단/경고 | 검색에서 미끄러지는 입구를 막음 | P1 |
| B3 | 앱·SNS 위험 줄이기 | 자극 피드 진입을 늦추는 마찰 | P2 |
| B4 | SNS 이미지 모자이크 | (연구) 노출 이미지 흐리기 | P3 |

### 2.1 무엇이 **아닌가** (정직성 경계)

- 실드는 **감시 도구가 아니다.** 방문 기록을 서버로 모아 보여주는 기능이 아니다.
- 실드는 **완벽한 차단이 아니다.** 사용자가 끄거나 우회할 수 있고, 우리는 그 사실을
  숨기지 않는다.
- 실드는 **처벌이 아니다.** 막혔을 때의 카피는 비난이 아니라 "여기서 잠깐 멈추자"다
  (샤임 카피 금지 — 규율 화면의 "나를 벌주기 위한 약속이 아니라"와 같은 결).
- 실드는 **아직 동작하지 않는다(이번 라운드).** 그래서 켜는 스위치를 두지 않는다.

---

## 3. 왜 SNS 인앱 이미지 모자이크는 P0가 아닌가

이 결정은 제품 신뢰의 핵심이라 명시한다.

1. **기술적으로 신뢰할 수 없다.** 타사 SNS 앱 화면을 가로채는 것은 iOS에서 불가능,
   Android에서는 접근성/오버레이 권한 남용에 가까워 정책 위반 위험이 크다(자세한 내용은
   Feasibility §2.6).
2. **온디바이스 비전 모델도 오탐/누락이 많다.** "가려졌다"고 약속했다가 한 장이라도
   새면 사용자 신뢰가 무너진다. 자극에 취약한 순간일수록 거짓 안심은 해롭다.
3. **"되는 척"은 NoF의 제1원칙 위반.** 우리는 동작하지 않는 보호를 동작하는 것처럼
   보이게 하지 않는다.

→ 따라서 모자이크는 **P3에서 정확도·지연·배터리만 연구**하고, 검증 전에는 제품 어디에도
"모자이크된다"고 쓰지 않는다.

---

## 4. 차단을 어떻게 제공할 것인가 (전달 경로)

사용자에게 보이는 "실드"는 하나지만, 뒤에서는 플랫폼별로 다른 엔진이 붙는다. 자세한
타당성은 Feasibility 문서. 요약:

- **Chrome 확장 (P1)** — 데스크톱에서 도메인/검색 차단을 가장 빨리 제공.
- **NoF 안전 브라우저 (P1)** — 모바일에서 "안전하게 탐색하는 방". 우리 브라우저 안에서는
  URL/검색어를 완전히 통제.
- **iOS Safari Content Blocker (P2)** — 사파리 전역 도메인 차단.
- **iOS Screen Time / FamilyControls (P2)** — 기기 전역 앱/웹 제한(가장 강력, 가장 비쌈).
- **Android VPN/DNS 로컬 필터 (P2)** — 기기 전역 도메인 차단(루트 불필요, 온디바이스).

각 경로의 공통 카피 원칙: **"기기 안에서만 동작 · 본 것을 서버로 보내지 않음 · 우회
가능함을 인정"**.

## 5. 실드는 NoF의 나머지와 어떻게 이어지는가 (Integration)

실드는 독립 기능이 아니라 **기존 절제 루프의 한 겹**이다. 연결점:

### 5.1 금욕 카운터(counters)와의 연결
- 카운터별로 "무엇을 멀리 둘지"를 정한다. 예: `콘텐츠 절제` 카운터 → 성인 사이트/검색 차단 룰,
  `SNS 줄이기` 카운터 → 숏폼/피드 마찰.
- 실드가 막은 순간이 카운터를 직접 리셋하지는 **않는다.** 차단은 카운터를 *돕는* 보호막.

### 5.2 규율(rules)과의 연결
- 규율은 "내가 정한 기준"이다(예: "자극 검색하지 않기"). 실드는 그 규율을 **실행으로**
  옮긴다 — "이 사이트 안 열기" 같은 규율에 차단 룰을 이어붙인다.
- 데이터 모델상 규율은 이미 `counterId`로 카운터에 연결된다(보조 약속). 실드 룰은 그
  연결 위에 얹는다. 규율을 못 지켜도 타이머는 리셋되지 않는다(기존 불변식 유지).

### 5.3 잠깐 멈춤(urge 5분 타이머)와의 연결
- **차단에 막힌 순간이 "잠깐 멈춤"의 트리거가 된다.** 사이트가 막히면 비난 대신 "5분만
  흘려보낼까요?"로 자연스럽게 `urge` 화면으로 잇는다.
- 이것이 실드의 핵심 UX: 차단은 끝이 아니라 **대처 도구로 가는 입구**.

### 5.4 기록(records / DayRecord)과의 연결
- "멀리 둔 순간"(차단이 마찰을 만든 순간)을 기록에 남겨, 최근 기록·복기에서 흐름을
  돌아볼 수 있게 한다. 단, **무엇을 보려 했는지가 아니라 "잘 멈췄다"는 사실만** 남긴다
  (프라이버시·비수치심 원칙).

## 6. 이번 라운드 UI 스펙 (P0 플레이스홀더 + P0.5 비집행 위험 신호 Planner + Safe Browser PoC, 구현됨)

> 실제 차단 없음. "차단 설정 / NoF 실드 · 준비 중" 안내 + **비집행 위험 신호 계획(Planner)**.
> 안전 핵심: 이 Planner는 **URL 목록이 아니다.** 사용자에게 위험한 사이트를 찾거나
> 붙여넣게 하지 않는다 — 자극 사이트를 검색해 주소를 복붙하는 행위 자체가 재발
> 트리거이기 때문이다. 그래서 추상 신호(카테고리·검색 신호·앱·SNS·상황)만 다룬다.

### 6.1 진입점 (Home)
- 홈의 보조 영역(`home-secondary`)에 카드 1개: 라벨 "차단 설정 · NoF 실드",
  `준비 중` pill, 정직한 한 줄("아직 실제 차단은 제공하지 않아요"), 버튼 "실드 준비 상황
  보기" → `shield` 화면.

### 6.2 실드 화면 (`ShieldScreen.jsx`)
구성(모두 읽기 전용, **토글·스위치 없음**):
1. **상태 카드** — `준비 중` pill + "아직 실제 차단은 제공하지 않아요" + "동작하지 않는
   기능을 켜진 것처럼 보이게 하고 싶지 않아 스위치를 두지 않았다"는 정직한 메모.
2. **위험 신호 계획(Planner, P0.5)** — 멀리 둘 **카테고리·검색 신호·앱·SNS·상황**을 골라
   카운터별로 묶어 보는 **비집행** 계획(추가·치우기). 사용자에게 위험한 사이트 주소를
   직접 찾아 적게 하지 않는다(그 검색 자체가 재발 트리거). 항상 "위험한 사이트를 직접
   찾아 적지 마세요" 안전 안내 + "**지금 입력한 신호는 아직 실제 차단에 쓰이지 않아요 ·
   실제 차단은 Safe Browser 또는 브라우저 확장 단계에서 동작해요**" 명시 + "이 목록은 아직
   차단에 쓰이지 않아요" 배너. 토글 없음. 이 신호는 P1 엔진이 준비되면, 앱이 관리하는
   큐레이션 차단 팩으로 매핑한다(사용자가 도메인을 찾는 게 아니다).
3. **앞으로 연결될 보호 방식 (로드맵)** — 브라우저 확장(1단계), NoF 안전 브라우저
   (**앱 안에서만 실험 가능**), iOS·Android 기기 차단(2단계). **켜는 버튼이 아니라** 순서를
   보여주는 읽기 전용 로드맵(타임라인)으로, 누를 수 있는 컨트롤처럼 보이지 않게 한다.
   SNS 이미지 모자이크는 "아직 연구 단계"로 한 줄.
4. **안전 브라우저 실험 (PoC, `SafeBrowserScreen.jsx`)** — "안전 브라우저 실험 열기"로 진입.
   **앱 안에서만** 동작하는 데모다: 실제 웹을 열지 않고(네트워크·iframe·외부 이동 없음),
   입력한 테스트 문구를 내가 정한 위험 신호와 **로컬 비교**한다. 닿으면 "이 신호는 멀리
   두기로 정했어요 · 5분만 늦춰볼까요?" 인터스티셜 → `잠깐 멈춤`. 안 닿으면 "이 실험에서는
   실제 웹을 열지 않아요". 위험한 실제 사이트를 찾게 하지 않는다.
5. **실드와 NoF가 이어지는 방식** — §5의 연결(카운터·규율·잠깐 멈춤·기록)을 미래형으로.
6. **실드가 준비되는 동안** — 지금 쓸 수 있는 도구로 잇는 버튼: `잠깐 멈춤`, `규율`.
7. **프라이버시 한 줄** — "기기 안에서만 동작 · 본 것을 서버로 보내지 않음" 원칙.

### 6.3 카피 원칙 (검수 기준)
- 현재형 차단 주장 금지: "차단했어요 / 차단하고 있어요 / 차단 중이에요 / 막고 있어요" ✖.
- 미래형·준비형만: "준비하고 있어요 / 켤 수 있게 할게요 / 제공하지 않아요" ✔.
- 샤임 카피 금지. 성인 이미지·노골적 표현 금지.
- 비집행 원칙: Planner는 데이터만 편집한다 — 어떤 트래픽도 막지 않고, `shield.js`에
  실제 도메인/노골적 표현을 담지 않는다(시드는 비어 있음).
- 안전 원칙: 사용자에게 위험한 사이트를 직접 찾거나 붙여넣게 하지 않는다. UI는 주소·
  도메인·URL·링크 같은 입력 개념을 노출하지 않고, 추상 신호(카테고리·검색 신호·앱·SNS·
  상황)만 다룬다. "위험한 사이트를 직접 찾아 적지 마세요" 안내를 항상 보인다.
- 혼동 방지: Planner만으로는 **아무것도 막지 않는다.** "지금 입력한 신호는 아직 실제
  차단에 쓰이지 않아요"를 명시하고, 보호 방식 로드맵은 **누를 수 있는 버튼처럼 보이지
  않게** 한다. 실제 차단 시연은 **앱 안에서만** 도는 Safe Browser PoC뿐이다(외부 웹·OS·
  SNS 차단을 한다고 주장하지 않는다).
- 회귀 가드: `scripts/nof-regression-check.mjs` #29(플레이스홀더 정직성)·#30(위험 신호
  Planner 비집행 + 위험 주소 미요구)·#31(Planner 비차단 명시 + 로드맵 비버튼 + Safe Browser
  PoC 앱 내 전용·매치 시 잠깐 멈춤)이 위 불변식을 정적으로 검증한다.

---

## 7. 성공 기준 (제품 관점)

- 사용자가 실드 화면을 보고 **"아직 안 되지만, 진심으로 준비 중이고, 어떻게 막을지
  계획이 있다"** 고 느낀다.
- 어떤 사용자도 "이미 차단되는 줄 알았는데 아니었다"는 배신감을 느끼지 않는다.
- 실드가 기존 루프(카운터·규율·잠깐 멈춤·기록)와 **이질적이지 않게** 얹힌다.
