## P0 — 제품 아키텍처 + UI 플레이스홀더 (이번 라운드, 완료 대상)

**목표**: 차단을 *구현하지 않고*, 제품 구조와 정직한 진입점을 만든다.

**산출물**
- `docs/NOF_SHIELD_FEASIBILITY.md` — 플랫폼별 타당성/한계/리스크.
- `docs/NOF_SHIELD_PRODUCT_SPEC.md` — 실드 정의·경계·연결·UI 스펙.
- `docs/NOF_SHIELD_ROADMAP.md` — 본 문서.
- `src/screens/ShieldScreen.jsx` — "차단 설정 / 준비 중" 안내 화면(읽기 전용, 토글 없음).
- 홈 진입 카드 + `shield` 라우트.
- 회귀 가드 #29 (실드 정직성 정적 검증).

**합격 기준 (P0 Acceptance)**
- 문서가 P0/P1/P2/P3를 명확히 분리한다.
- UI는 **가짜 차단·가짜 토글·현재형 차단 주장**이 없다.
- 성인 이미지/노골적 표현/샤임 카피 없음.
- 기존 `npm run build`, `npm run check:nof` 가 그대로 통과한다.

**P0에서 하지 않는 것**: 어떤 OS 레벨 차단도 구현하지 않는다.

## P0.5 — 위험 신호 계획(Risk-signal Planner), 비집행 (구현됨)

**목표**: 차단 *엔진 없이*, 사용자가 "나중에 멀리 둘 위험 신호"를 미리 정해두는 **계획**을
만든다. 아무것도 막지 않는다 — P1 엔진이 준비되면 이 신호를 그대로 입력으로 쓴다.

**안전 원칙 (가장 중요)**: 사용자에게 위험한 사이트를 직접 찾거나 붙여넣게 **하지 않는다.**
자극 사이트를 검색해 주소를 복붙하는 행위 자체가 재발 트리거이기 때문이다. 그래서 Planner는
주소·도메인·URL·링크 개념을 다루지 않고, 추상 신호만 다룬다: **카테고리 · 검색 신호 ·
앱·SNS · 상황**. P1 엔진이 이 신호를 받아, **앱이 관리하는 큐레이션 차단 팩**으로 매핑한다
(사용자가 도메인을 찾는 게 아니다).

**산출물**
- `src/constants/shield.js` — 위험 신호 데이터 모델(`{ id, kind, label, counterId }`,
  `kind ∈ {category, keyword, appCategory, situation}`), 추상 제안(실제 도메인/검색어 아님),
  빈 시드(`DEFAULT_BLOCKLIST = []`), 헬퍼(`makeBlockEntry` · `summarizeBlocklist` ·
  `entriesForCounter`).
- `src/App.jsx` — `blocklist` 상태 + `addBlockEntry` / `removeBlockEntry`(비집행).
- `src/screens/ShieldScreen.jsx` — 신호 추가(종류·라벨·카운터 연결) / 카운터별 묶어
  보기 / 치우기. 토글 없음. 항상 보이는 "위험한 사이트를 직접 찾아 적지 마세요" 안전 안내 +
  "이 목록은 아직 차단에 쓰이지 않아요" 배너.
- 회귀 가드 #30.

**합격 기준 (P0.5)**
- 신호를 추가하면 연결한 카운터 아래에 묶여 보이고, 치우면 사라진다.
- 현재형 차단 주장 없음, 동작하는 토글/스위치 없음.
- UI에 주소·도메인·URL·링크 같은 입력 개념이 **없다**(위험 사이트를 찾게 하지 않는다).
- `shield.js`에 실제 도메인/노골적 표현 없음, 시드는 비어 있음, `kind`는 4종 추상 신호.
- 기존 `npm run build`, `npm run check:nof` 통과(이번엔 #30 포함).

**P0.5에서 하지 않는 것**: 이 신호로 **무엇도 차단하지 않는다.** 집행은 P1. 사용자에게
위험한 주소를 찾게 하지 않는다.

## P0.6 — Safe Browser PoC, 앱 내 전용 (구현됨)

**목표**: P0.5의 위험 신호가 **무엇을 하려는지**를 사용자가 직접 체감할 수 있게, 차단
*엔진 없이* **앱 안에서만** 도는 작은 시연을 붙인다. Planner만으로는 아무것도 막지 않으니,
"막힘 → 잠깐 멈춤"의 흐름을 안전하게 미리 보여 준다.

**동작**
- `src/screens/SafeBrowserScreen.jsx` + 라우트 `shieldBrowser`. 실드 화면의 "안전 브라우저
  실험 열기"로 진입.
- 사용자가 **해롭지 않은 테스트 문구**를 입력 → `matchSignals()`(shield.js)가 내가 정한
  위험 신호 라벨과 **로컬 대소문자 무시 부분일치**로 비교. **네트워크·iframe·외부 이동
  없음**.
- 닿으면: 아무것도 열지 않고 "이 신호는 멀리 두기로 정했어요 · 5분만 늦춰볼까요?"
  인터스티셜 → `잠깐 멈춤(urge)`. 안 닿으면: "이 실험에서는 실제 웹을 열지 않아요".
- 위험한 실제 사이트를 찾거나 붙여넣게 **하지 않는다**(placeholder도 추상 신호 예시만).

**합격 기준 (P0.6)**
- 실드가 "Planner만으로는 차단하지 않는다"를 명시하고, 보호 방식 카드는 **버튼이 아니다**.
- Safe Browser는 **외부 링크를 열지 않는다**(http·iframe·window.open·href 없음).
- 매치 시 `잠깐 멈춤`으로 이어진다.
- 회귀 가드 #31 통과 + 기존 `npm run build`·`npm run check:nof` 통과.

**P0.6에서 하지 않는 것**: 외부 웹/OS/SNS를 **실제로 차단하지 않는다.** 이건 어디까지나
**프로토타입 안 시연**이다. 진짜 차단은 P1(확장/안전 브라우저)·P2(기기)에서. SNS 이미지
모자이크는 여전히 P3 연구만.

## P1.0 — Chrome 확장 차단 PoC, 로컬 전용 (구현됨)

**목표**: P1 경로 A(Chrome 확장)의 가장 작은 *실제로 동작하는* 슬라이스를, 외부 위험 없이
로컬에서만 검증한다. 해롭지 않은 테스트 신호 하나만 막아, "막힘 → 잠깐 멈춤" 흐름이 진짜
브라우저 탐색에서도 도는지 보여 준다.

**산출물**: `extensions/chrome-shield/` (Manifest V3)
- `manifest.json` — `declarativeNetRequest` 권한 + 정적 룰셋(`rules.json`), 모듈 서비스 워커.
- `rules.json` — 정적 룰: 최상위 내비게이션의 URL/검색어에 `nof-test-risk-signal` 이 들어가면
  앱 내 멈춤 페이지(`blocked.html`)로 **redirect**(대소문자 무시, main_frame 한정).
- `signals.js` — 로컬 위험 신호 모델 + `buildDynamicRules()`(신호 → DNR 동적 룰). 무해한
  테스트 토큰만 시드한다(실제 도메인·노골적 표현 없음).
- `service_worker.js` — 동적 룰 동기화 경로(`updateDynamicRules`). 향후 NoF 앱이
  `chrome.runtime.sendMessage({ type: 'nof:set-signals', signals })` 로 위험 신호를 보내면
  로컬에서 동적 룰을 다시 만든다(정적 데모 룰 id 1은 항상 유지, 동적 룰은 id ≥ 1000).
- `blocked.html` / `blocked.js` — NoF "잠깐 멈춤" 페이지. 어디로 가려 했는지는 보여주지
  않고, 5분 멈춤 타이머를 그 자리에서 돌린다. 외부 이동 없음.
- `popup.html|js`, `options.html|js` — 상태/테스트 신호 표시, 향후 앱 신호 동기화 설명.
- `README.md` — 로드/테스트 방법, 한계(Chrome 데스크톱 전용), 앱 신호 동기화 설계.
- 회귀 가드 #32.

**동작 / 합격 기준 (P1.0)**
- `nof-test-risk-signal` 이 든 주소로 이동하면 멈춤 페이지로 redirect 된다.
- 닿지 않는 주소는 그대로 통과한다(차단 없음).
- 멈춤 페이지는 방문 대상을 보여주지 않고, "잠깐 멈춤으로 가기"를 제공한다.
- 네트워크·원격 코드·CDN·외부 API 없음(완전 로컬). 성인 도메인·표현 없음.
- 기존 `npm run build`·`npm run check:nof`(가드 #32 포함) 통과.

**앱 신호 동기화(설계, 다음 단계)**: 사용자는 위험한 주소를 직접 찾지 않는다. NoF 앱의
추상 위험 신호(카테고리·검색 신호·앱·SNS·상황)를 **앱이 관리하는 큐레이션 토큰**으로
매핑해 확장에 메시지로 보내고, 확장은 그 토큰으로 동적 룰을 만든다.

**P1.0에서 하지 않는 것**: 실제 성인 사이트 목록을 막지 않는다(테스트 신호 한 개뿐).
모바일(iOS·Android)·SNS 앱·이미지 모자이크 차단이 **아니다.** 그건 P2/P3.

## P1 — URL/검색어 차단: 확장 또는 안전 브라우저 (다음 구현)

**목표**: **실제로 동작하는 첫 차단**을 가장 낮은 리스크로 내놓는다. 둘 중 하나로 시작
(병행 아님):

> 입력은 P0.5의 **위험 신호**다. 엔진은 사용자가 고른 카테고리·검색 신호·앱·SNS·상황을
> **앱이 관리·갱신하는 큐레이션 차단 팩**(도메인/검색 룰)으로 매핑한다. 사용자는 위험한
> 주소를 직접 찾거나 붙여넣지 않는다 — 그 검색 자체가 재발 트리거이기 때문이다.

### 경로 A — Chrome 확장 (데스크톱 우선)
- Manifest V3 `declarativeNetRequest`로 도메인/URL 차단(B1).
- 콘텐츠 스크립트로 자극 검색어 경고/흐림(B2).
- 차단 룰은 로컬 저장 → 방문 기록 서버 전송 없음.

### 경로 B — NoF 안전 브라우저 (모바일 우선)
- `WKWebView`/`WebView` 래퍼. 우리 브라우저 내부에서 URL 화이트/블랙리스트(B1) +
  검색어 가로채기(B2)를 완전 통제.
- 막힌 순간 → `잠깐 멈춤(urge)` 5분으로 잇는 UX 연결(Product Spec §5.3).

**선택 기준**: 초기 사용자 다수가 데스크톱이면 A, 모바일 중심이면 B. **권장: B(안전
브라우저)** — NoF는 모바일 앱이므로 사용자 여정이 자연스럽다.

**합격 기준 (P1)**
- 알려진 성인 도메인 목록이 실제로 막힌다(테스트 도메인으로 검증).
- 자극 검색어 입력 시 경고/흐림이 뜬다.
- 카피가 한계를 명시한다: "완벽한 벽이 아니라 마찰 · 우회 가능 · 기기 안에서만 동작".
- 차단 이벤트가 카운터/규율/잠깐 멈춤/기록과 연결된다(Product Spec §5).
- **P1 전까지 실드 화면은 "준비 중"을 유지**한다. 동작 검증 후에만 "켜기"를 노출.

**리스크**: 우회 가능성(정직하게 고지), 확장 스토어/앱 심사 정책 준수.

## P2 — 네이티브 기기 차단 (iOS / Android)

**목표**: "우리 브라우저 안"을 넘어 **기기 전역** 차단. 비용·심사 리스크가 크므로 P1의
가치가 검증된 뒤 착수.

### iOS
1. **Safari Content Blocker (먼저)** — 선언적 룰로 사파리 전역 도메인 차단(B1).
   프라이버시 우위(NoF가 방문 내용을 못 봄). 심사 리스크 중.
2. **Screen Time / FamilyControls (그다음)** — `ManagedSettings`·`DeviceActivity`로
   앱/웹 전역 제한(B1·B3). **특별 엔타이틀먼트 필요** → 승인 리스크가 P2의 최대 변수.

### Android
- **VPNService 기반 로컬 DNS 필터** — 루트 없이 기기 전역 도메인 차단(B1). 트래픽을
  외부로 보내지 않고 로컬에서 DNS 응답만 거른다. HTTPS 본문 검사는 하지 않는다(도메인
  레벨까지가 정직한 한계).

**합격 기준 (P2)**
- iOS: Content Blocker가 사파리에서 도메인 차단. (Screen Time는 엔타이틀먼트 승인 시.)
- Android: 로컬 VPN/DNS 필터가 기기 전역에서 도메인 차단, 배터리/안정성 허용 범위.
- 프라이버시 원칙 유지(온디바이스, 무전송, TLS MITM 금지).
- 심사 제출용 용도 고지/데모/정책 페이지 완비.

**리스크**: FamilyControls 엔타이틀먼트 거절, Google Play의 VPN/접근성 권한 심사.

## P3 — SNS 이미지 모자이크 (연구만, 구현 약속 없음)

**목표**: 노출 이미지를 흐리게 하는 것이 **신뢰할 수준으로 가능한지**만 검증. 제품에
노출하지 않는다.

**범위**
- 온디바이스 비전 분류기의 **정확도/오탐/누락**, **지연**, **배터리** 측정.
- 적용 가능한 유일한 정직한 표면은 **NoF 안전 브라우저 내부의 웹 SNS**(타사 네이티브 앱
  화면 가로채기는 불가/정책 위반).

**합격 기준 (P3)**
- "가려진다"고 약속할 수 있을 만큼 정확도가 충분한지 **판단을 내리는 리서치 노트** 산출.
- 충분하지 않으면 **출시하지 않는다** — 그것도 정직한 결론이다.

**P3에서 하지 않는 것**: 검증 전 어떤 "모자이크됩니다" 카피도 제품에 넣지 않는다.

## 단계 게이트 원칙 (요약)

1. 각 단계는 **앞 단계가 정직하게 끝난 뒤** 시작한다.
2. 실드 UI는 **실제 동작이 검증되기 전까지 "준비 중"** 을 유지한다.
3. 모든 단계에서 프라이버시(온디바이스·무전송·MITM 금지)와 비수치심 카피를 지킨다.
4. 우회 가능성은 항상 인정한다 — 실드는 "벽"이 아니라 "마찰"이다.
